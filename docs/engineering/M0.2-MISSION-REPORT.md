## Findings addressed and evidence

### A. Security batteries (was Critical, M0.1 F1)

- Before: `pull_request` job received production Supabase secrets. After: `tests/unit/workflow-secret-boundary.test.ts` (8 tests) asserts no `pull_request_target`/`workflow_run`, no sensitive secret reachable from PR-capable jobs, credentialed jobs master-gated + environment-gated, blocked→fail. Verified to fail against the old workflow (6 failures) and pass on the new one.
- Residual: the credentialed jobs still use whatever secrets the owner stores in `security-batteries`; the owner should supply a least-privilege, non-production credential. Environment protection is not enforced until the owner configures it.

### B. Historical credentials

- Commit `144e60c9` (2026-08-15) committed `.env` and `.mcp.json`; `b1eef496` (2026-09-03) removed them. Categories: Supabase service-role + anon/publishable keys (old project, not production), a GitHub PAT, an NVIDIA API key. Rotation evidence in repo: **none**. Liveness not tested (no authority). Git history still contains them; rotation, not history rewrite, is the remedy.

### C. Deployment governance

- All upstream environments (`copilot`, `infrastructure-apply`, `infrastructure-plan`, `Preview`, `Production`) have no protection rules, no branch policy, admin bypass allowed. `release.yml` and `verify.yml` reference `production`; names are case-insensitive. Manifest requires reviewers, master-only policy, no admin bypass, self-review prevention on Production.
- Not changed: `nightly-db-backup.yml` uses prod DB secrets with no environment; adding reviewers would break unattended backups. Owner decision (separate non-reviewer environment with a master-only policy).
- `verify.yml` `preview` job gives Vercel tokens to same-repo PRs (not Supabase). Residual, documented.
- Approval is **not enforced** until the owner applies the manifest.

### D. CI / billing lock

- Observed: "The job was not started because your account is locked due to a billing issue." Run 43023838839 (Verify, PR #348) created 2026-11-11T12:50:35Z; same for 43023838726 and 43028755579. Owner is org `Sherivs`; only the org owner can resolve. Nothing changed.
- Local alternative: `npm run verify:local` → `artifacts/local-gate.json` (exit 0 PASS, 1 FAIL, 3 INCOMPLETE; NOT_RUN never counts as PASS). Result on this machine: PASS Typecheck, Unit tests (567 files / 10,370 tests), Registry/drift/neutrality/secrets + build, Mobile typecheck; NOT_RUN gitleaks (not installed) and migration dry-run (needs Docker/Postgres 17).
- Required checks (exact `verify.yml` job names, enforced by test): Typecheck; Lint (changed files); Unit tests; Secret scan (gitleaks); Registry, drift, neutrality, secrets guards + build; Migration dry-run + sim smoke; Mobile typecheck (Expo). Deliberately not required: Security Batteries, Infrastructure verify (path-scoped), E2E, Vercel jobs.
- Safe sequencing: **do not apply the ruleset while the lock persists** (required checks would block every merge). Order: restore billing → confirm checks green on a PR → apply ruleset.

### E. Security governance

- Dependabot config adequate (npm, /mobile, github-actions, grouped). All workflows declare `permissions`; actions SHA-pinned (existing tests). No CodeQL workflow exists; `repo-settings.json` requests default setup (not an advanced workflow, to avoid conflict).
- Not readable with the available token (403): secret scanning, push protection, Dependabot alert state (M0.1 reported disabled), Actions default token permissions, repo secrets. Marked unverified.
- CODEOWNERS with a single owner means an owner-authored PR cannot self-approve under code-owner review; a second owner/team is required.
