MEMORY + CONTEXT FABRIC

Architecture status: SCOPE LOCKED

Block 08 gave CoreGrid actors.

Block 09 gives those actors continuity.

The fundamental question is:

> How does CoreGrid remember what matters, understand what is relevant now, retrieve the right history, preserve provenance and authority, and construct the exact context required for a person, agent, workflow, or intelligence task—without confusing memory with knowledge, reality, or identity?




---

01. THE CORE MEMORY AXIOM

A conventional AI system often looks like:

Conversation
    ↓
Chat History
    ↓
LLM Context

CoreGrid becomes:

REALITY
  ↓
OBSERVATIONS
  ↓
EVENTS
  ↓
EXPERIENCES
  ↓
MEMORY
  ↓
KNOWLEDGE
  ↓
CONTEXT
  ↓
INTELLIGENCE / AGENTS

But these layers are not interchangeable.

Memory is not Knowledge.

Memory answers:

> What has been experienced, recorded, decided, learned, or intentionally retained?



Knowledge answers:

> What does CoreGrid currently know or believe to be supported by evidence?



Memory is not Reality.

Reality records what happened.

Memory records what CoreGrid retains about what happened.

Memory is not Identity.

Identity determines whose memory it is and who may access it.


---

02. COREGRID MEMORY FORMULA

MEMORY
=
CONTENT
+
MEANING
+
OWNER
+
SCOPE
+
TIME
+
PROVENANCE
+
CONFIDENCE
+
AUTHORITY
+
RETENTION
+
LINEAGE
+
STATUS

Therefore a memory cannot simply be:

"text": "Customer likes blue shirts"

It needs context:

Who?
When?
How was this learned?
Is it still valid?
Who can access it?
Why was it retained?
How reliable is it?
Can it be corrected?
When should it expire?
