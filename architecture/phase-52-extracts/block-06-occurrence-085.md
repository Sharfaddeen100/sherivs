BLOCK 06 — THE TWO-LAYER UI MODEL

Every organization gets:

Layer A — Domain UI

Generated from the domain's invariant experience.

Example:

Every restaurant gets appropriate primitives for:

menu

orders

reservations

tables

customers

inventory

payments


But not necessarily the same layout.


---

Layer B — Reality UI

Generated from that specific organization's reality.

Restaurant A:

> 12 tables, dine-in heavy, 2 branches, no delivery.



Restaurant B:

> 40 tables, delivery-heavy, 6 branches, large kitchen, multiple suppliers.



Their CoreGrid workspaces should therefore differ.

Formula

DOMAIN UI
        +
ORGANIZATION REALITY UI
        +
ROLE UI
        +
CURRENT REALITY
        +
USER PREFERENCE
        ↓
FINAL EXPERIENCE

That is the architecture I would lock.
